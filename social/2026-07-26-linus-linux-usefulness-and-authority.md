## Working brief

- **Reader:** People following the argument about Linus Torvalds’s LLM stance and tante’s response.
- **Job:** Separate Linux project governance from a general moral defence of AI.
- **Claim:** Linus can reject a categorical Linux ban because LLMs are useful in kernel work; critics need evidence of Linux-specific harm and a rule that addresses it.
- **Boundary:** This does not settle broader ethical questions about LLMs or make their use harmless.
- **LinkedIn formatting:** Plain text only.

## LinkedIn post

I agreed with Linus when I saw the post: Someone brought the broader argument about LLMs to the Linux kernel mailing list. Linus said Linux would not become an anti-AI project. If that was a requirement, people could fork it or leave.

Yeah. He runs Linux.

Tante’s response is that usefulness is not sufficient. I kept reading Linus as making a project decision; tante read him as making a moral claim about AI. That’s where the argument comes apart.

The decision in front of Linus was whether Linux should prohibit LLMs, something - some - kernel developers find useful. A ban has costs too. Critics need more than an analogy to justify excluding it.

Maybe LLM-assisted patches create licensing problems. Maybe they contain defects that are unusually difficult to catch, or push more work onto maintainers. I don’t know. Find the patches. The critics should show where the existing process fails. Then ask Linux to change the rules.

Child labor and asbestos analogies don’t show that LLM use is causing a particular harm in Linux, or that a ban would reduce it. They remind us that useful things can cause harm. Fine. Which harm is happening in Linux? Who is harmed? What rule would reduce harm?

Linux has never been governed by whoever presents ethical critique. Linus makes the call. Open source gives everyone else somewhere to take the code when they disagree. “Fork it or walk away” is harsh. It is also what open source leaves you when the maintainer says no.

If someone can show the kernel problem, I’ll reconsider. Tante's argument doesn’t.

## Second comment

Related: Frédéric Bastiat, “That Which Is Seen, and That Which Is Not Seen”
https://bastiat.org/en/twisatwins.html

Bastiat’s point is to count indirect and forgone effects, not only the immediate effects we can see. Critics are right to ask about costs an LLM user may not see. But a ban has unseen costs too: useful work not done, access lost, review or diagnostic gains forgone, and capability left to well-funded proprietary teams. Those are claims to investigate, just like the claimed harms. The relevant comparison is LLM use under Linux’s contribution process versus prohibition, with the costs and benefits of both counted.
